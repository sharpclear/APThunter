# algorithm_integration

当用户要求把新算法、新检测类型、新模型能力接入 APTHunter 的检测、订阅或预警流程时使用本 skill。

## 必读上下文

1. 先执行 `git status --short`，确认工作区已有改动，不覆盖用户改动。
2. 阅读仓库根目录 `AGENTS.md`。
3. 阅读本 skill 参考文档：`references/algorithm_integration.md`。
4. 如果仓库存在 `backend/app/docs/new_algorithm_integration_guide.md`，也读取它作为成员协作文档。

## 执行原则

- 先判断新算法是否能复用已有 `model_category` / `task_type`，不要默认新增数据库枚举。
- 如果是全新业务模块，必须同步数据库结构、SQLAlchemy 枚举、初始化 SQL、已有库迁移、后端流程和前端展示。
- 接入范围必须覆盖用户要求的链路；当用户说“接入系统流程”时，默认同时检查手动创建检测任务、订阅、预警、数据库和前端入口。
- 算法代码优先封装为 `backend/app/models/<algorithm_key>_detection.py` 适配器，业务服务负责数据库、MinIO、任务状态和通知副作用。
- 高风险判定、默认阈值、自定义阈值映射不明确时，先向用户索取规则，不要猜测。

## 标准流程

1. 收集或整理算法接入卡：算法标识、输入、输出、模型路径、依赖、阈值、订阅规则、预警字段、验收样例。
2. 判定接入类型：复用现有类型、同类算法适配、还是新增业务类型。
3. 检查手动创建检测任务流程：API、文件上传、任务入库、Celery 投递、执行器、结果保存、任务列表和结果下载。
4. 检查订阅和预警流程：可订阅模型、订阅创建、调度执行、高风险提取、Alert 创建、预警 JSON 归档、邮件/飞书通知。
5. 检查数据库交互：权限、事务、状态流转、MinIO 文件索引、错误回滚、已有数据卷兼容。
6. 如新增业务类型，补数据库结构、初始化脚本和 migration。
7. 如影响前端，补检测页面、路由、订阅页类型、阈值说明、预警展示和任务结果展示。
8. 按改动范围运行验证，最终说明变更、验证和未覆盖风险。

## 交付要求

- 只改本次接入必要文件。
- 不提交真实密钥、大模型、训练数据、每日数据 zip、日志、缓存或构建产物。
- 不要求用户重建 MySQL 数据卷来获得结构变更，必须提供幂等迁移。
- 最终回复列出改动文件、执行过的验证命令和未执行验证的原因。
